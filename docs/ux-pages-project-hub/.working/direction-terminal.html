directory listing.

the hub reads like ls in your own projects folder: one dense line per thing, all lowercase, nothing louder than it needs to be. it's mostly a jump-list for me, so it should be fast to scan and fast to leave.

"maker log" shows up literally: a git log of the last commits sits under the list, and every project page is a cat README. the nav strip is a dark status bar with an amber edge, so it never blends into the app below.

# zcal

single-user scheduling: read one calendar, publish availability, book a slot.

one person, one calendar, one sqlite file. no accounts, no telemetry.

screenshot: booking page
screenshot: pick a time
screenshot: booked, written back

what it does

  • reads one calendar (an .ics feed, an upload, or busy blocks by hand)
  • publishes your free time as bookable slots
  • a visitor reserves a slot. no account needed
  • writes the event back to that calendar

run it locally

shell
$ cd zcal
$ npm run bootstrap   # installs, writes .env, adds sample data
$ npm run dev         # → http://localhost:3000

needs node 20.9 or newer. it needs a server because it keeps your bookings in sqlite, so github pages can't host it.
